# 02 · 数据规范

> 目的：让每一篇文本都能被机器解析、被人工阅读、被精确引用，并且在版本变化后还能对得上。

---

## 1. 文件与 ID

### 1.1 文档 ID

格式：

```text
<类型>.<地区/主题>.<短名>
```

规则：

- 全小写 ASCII；
- 用 `.` 分层，用 `-` 连接单词；
- 一旦发布，不随标题翻译变化；
- 中文标题放在 `title`，不放进 ID。

示例：

```text
quest.archon.mondstadt.prologue-01
quest.story.liyue.zhongli-01
quest.world.mondstadt.time-and-wind
book.mondstadt.lindens-wind
char.liyue.zhongli
weapon.liyue.vortex-vanquisher
artifact.set.crimson-witch-of-flames
geo.liyue
event.mondstadt.unreconciled-stars
notice.1-0.version
concept.irminsul
```

### 1.2 实体 ID

实体与文档分开：

```text
entity.zhongli
entity.liyue
entity.wangsheng-funeral-parlor
entity.archon-war
entity.irminsul
```

实体 ID 不随称号变化。称号放 `entity_names.name_type = epithet`。

### 1.3 文件名

正文路径使用“人类可读”的目录和中文标题，ID 只放 front matter：

```text
corpus/quests/archon/mondstadt/1.0/01-捕风的异乡人.md
corpus/quests/story/liyue/钟离/古闻之章-第一幕.md
corpus/books/mondstadt/林间风.md
corpus/characters/liyue/钟离.md
corpus/weapons/liyue/护摩之杖.md
corpus/artifacts/染血的骑士道.md
corpus/geography/liyue/璃月.md
corpus/events/1.1-未归的熄星.md
corpus/notices/2020-09-28-版本更新说明.md
```

限制：

- 不用 Windows 禁用字符：`\ / : * ? " < > |`；
- 标题里的 `/` 用 `／` 或 `-`；
- 文件名不超过 120 个字符；
- 重命名文件时，同步更新 `related` 和 `document_links`；
- 不要用“最终版”“新版”这种会过期的词。

### 1.4 目录规则

| 类型 | 目录 | 拆分方式 |
|---|---|---|
| 魔神任务 | `corpus/quests/archon/<地区>/<版本>/` | 一幕一篇；系列任务可加 `00-系列总览.md` |
| 传说任务 | `corpus/quests/story/<地区>/<角色>/` | 一幕一篇 |
| 世界任务 | `corpus/quests/world/<地区>/` | 一个系列一篇，超长再拆 |
| 活动剧情 | `corpus/quests/event/<版本>-<活动名>/` | 一幕一篇 |
| 邀约 | `corpus/quests/hangout/<角色>/` | 一条线一篇 |
| 间章 | `corpus/quests/interlude/` | 一幕一篇 |
| 书籍 | `corpus/books/<地区>/` | 一本书一篇，卷为章节 |
| 散落文本 | `corpus/scattered/<地区>/` | 一条/一组同地点文本一篇；只收交互文本，不提取图片 |
| 角色 | `corpus/characters/<地区>/` | 一个角色一篇；只收故事/描述/语音，不收攻略/配队/数值 |
| 武器 | `corpus/weapons/<地区>/` | 一把武器一篇 |
| 圣遗物 | `corpus/artifacts/` | 一套一篇 |
| 地区 | `corpus/geography/<地区>/` | 一个地区/地点一篇 |
| 公告 | `corpus/notices/` | 一期公告一篇 |

## 2. Front matter

每篇 Markdown 以 YAML front matter 开头：

```yaml
---
id: quest.archon.mondstadt.prologue-01
type: quest
subtype: archon
title: 示例任务
title_en: Example Quest
language: zh-Hans
region: 蒙德
version: "1.0"
version_source: obc-filter
version_confidence: confirmed
release_date: 2020-09-28
canon_status: community
transcription: near-verbatim
spoiler:
  level: 1
  scope:
    - archon:mondstadt
source:
  - source_id: obc
    url: https://baike.mihoyo.com/ys/obc/content/399/detail
    page_id: "399"
    revision_id: "1761787170"
    retrieved_at: 2026-11-04T01:42:05+08:00
    license: site-policy
tags:
  - 蒙德
  - 西风骑士团
related:
  - char.mondstadt.venti
status: draft
notes: ""
---
```

### 2.1 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 稳定文档 ID，见 1.1 |
| `type` | 是 | `quest` / `book` / `character` / `weapon` / `artifact` / `item` / `voice` / `geography` / `event` / `manga` / `notice` / `lore` / `other` |
| `subtype` | 否 | 任务：`archon` / `story` / `world` / `event` / `hangout` / `interlude`；散落文本：`scattered`；物品：`material` / `food` / `quest-item` / `furnishing` |
| `title` | 是 | 中文标题，保留书名号/引号 |
| `title_en` | 否 | 英文标题，便于交叉检索 |
| `language` | 是 | 默认 `zh-Hans`；英文 `en`；日文 `ja` |
| `region` | 否 | 蒙德/璃月/稻妻/须弥/枫丹/纳塔/挪德卡莱/至冬/提瓦特/未知 |
| `version` | 否 | 游戏实装版本，字符串，如 `"1.0"`、`"6.0"`；找不到就留空 |
| `version_source` | 否 | 版本来源：`obc-filter` / `bwiki` / `official` / `manual` / `derived-related-quest` / `web` / `unknown` |
| `version_confidence` | 否 | 版本置信度：`confirmed` / `likely` / `inferred` / `estimated` / `unknown` |
| `release_date` | 否 | 现实发布日期，`YYYY-MM-DD` |
| `canon_status` | 是 | 内容权威性：`official` / `official-secondary` / `community` / `datamine` / `fan` / `unknown` |
| `transcription` | 是 | 文本保真度：`verbatim` / `near-verbatim` / `edited` / `summary` / `unknown` |
| `spoiler.level` | 是 | 0–3，见第 5 节 |
| `spoiler.scope` | 否 | 剧透范围标签，如 `archon:mondstadt`、`character:zhongli` |
| `source` | 是 | 至少一条；见 2.2 |
| `tags` | 否 | 主题标签，见第 6 节 |
| `related` | 否 | 相关文档/实体 ID |
| `status` | 是 | `draft` / `reviewed` / `stable` / `deprecated` |
| `notes` | 否 | 人工备注，不进入正文 |

### 2.2 `source` 结构

```yaml
source:
  - source_id: obc            # 必填，对应 sources.csv
    url: https://baike.mihoyo.com/ys/obc/content/399/detail  # 必填
    page_id: "399"             # 观测枢 entry_page_id
    revision_id: "1761787170"  # page.version（页面编辑版本，不是游戏版本）
    retrieved_at: 2026-11-04T01:42:05+08:00
    license: site-policy
    notes: "官方平台/社区编辑；非逐字官方文本"
```

规则：

- 一篇文档可以有多个来源；第一个是主来源；
- `source_id` 必须存在于 `manifests/sources.csv`；
- 观测枢来源：`page_id` 用 `entry_page_id`，`revision_id` 用 `page.version`，并在 `notes` 标注“社区编辑”；
- BWiki 来源必须记录 `revision_id`（MediaWiki revid），否则无法判断之后是否改过；
- 米游社来源记录 `post_id`（放 `page_id`）；
- 数据包来源记录 `package` 和 `version`，可放 `notes`。

### 2.3 不要放进 front matter 的字段

以下字段由脚本计算，不手写：

- `content_hash`；
- `char_count`；
- `raw_path`；
- `normalized_path`；
- `created_at` / `updated_at`。

这些放数据库，避免手改不一致。

## 3. 正文结构

### 3.1 通用规则

- UTF-8，LF 换行；
- 标题层级从 `##` 开始（`#` 留给文档标题，通常不写）；
- 中文标点保留原样，不自动转半角；
- 保留 `「」`、`『』`、`——`、`……`；
- 不“修正”原文错别字；必要处加 `<!-- 原文如此 -->`；
- 玩家角色统一写 `旅行者`，不替换成具体名字；
- 性别分支保留 `妹妹/哥哥` 原文，并加标签 `player-gender`；
- 选项全部保留，不合并分支；
- 说话者保持原文（包括 `???`、`？？？`、`神秘人`）。

### 3.2 任务

```markdown
## 任务信息

- 类型：魔神任务
- 地区：蒙德
- 版本：1.0
- 前置：...
- 后续：...

## 任务剧情

### 步骤名

> 场景：...

**派蒙**：...

**旅行者**：...

> 选项：
> - 选项 A
> - 选项 B

**派蒙**：...
```

约定：

- `###` 对应任务步骤；
- `**角色**：` 表示一句台词，使用全角冒号；
- `> 场景：` 表示任务描述/地点提示；
- `> 选项：` 后跟列表，保留全部选项；
- `> 注：` 表示 Wiki 注释/玩家补充，不算原文；
- 折叠内容照常展开，但在 front matter `notes` 或行内注释说明；
- 黑幕文本保留，`spoiler.level` 至少 2。

### 3.3 书籍

```markdown
## 卷一 · 标题

正文段落……

正文段落……

## 卷二 · 标题

……
```

约定：

- 一本书一篇；卷为 `##`；
- 保留 `<br>` 形成的自然段，不把整卷压成一段；
- 脚注/注释用 `[^1]`，文末放 `[^1]: ...`；
- 书名、作者、稀有度、获取地点放 `## 书籍信息`，不混进正文；
- 多卷本如果超过 5 万字，可拆成每卷一篇，用 `related` 互链。

### 3.4 角色

```markdown
## 更多描述

……

## 角色详细

……

## 角色故事 1

……

## 神之眼 / 神之心

……

## 角色关联语音

### 初次见面

**钟离**：……
```

约定：

- **只收游戏内叙事文本**：更多描述、角色详细、角色故事、神之眼/神之心、关联语音；
- 属性、稀有度、生日、所属、武器类型、命之座、配队、圣遗物推荐**不进正文**；
- 角色故事按游戏内解锁顺序编号；
- 语音按类别分 `###`，说话者写角色名；
- 皮肤/装扮文案单独一节；
- 角色页里的“攻略”内容丢弃。

### 3.5 武器 / 圣遗物

```markdown
## 故事

……

## 设定

- 类型：长柄武器
- 稀有度：5
- 所属：璃月
```

约定：

- 只收叙事文本，不收数值/突破材料；
- 圣遗物一套一篇，每个部位的故事为 `###`；
- 武器故事如果分“故事/设定/突破材料”，只保留故事和必要的设定说明。

### 3.6 地区 / 地理志

```markdown
## 地理志

……

## 描述

……

## 考据

> 注：以下为整理者补充，不是游戏原文。
```

约定：

- 原文和考据必须分开；
- 考据段落用 `> 注：` 或独立 `## 考据`；
- 不要把 Wiki 的攻略/采集点写进来。

### 3.7 散落文本

```markdown
## 交互文本

> *【残破的笔记】*
> *（记载着……的笔记。）*

> 「……」
```

约定：

- 只收石碑、笔记、留言、书页、告示等**交互文本**；
- 不提取地图截图、坐标、图标；图片最多在 `notes` 标 `needs_ocr`；
- 标题保留地点括注，如 `残破的笔记【废弃避难所】`；
- `type: lore`，`subtype: scattered`；
- 版本优先从“相关任务”推导；推导不到就留空，`version_confidence: unknown`，不要猜。

### 3.8 公告

```markdown
## 公告正文

……

## 版本信息

- 版本：1.0
- 上线日期：2020-09-28
```

公告通常不是“世界观文本”，但能提供版本、活动、角色上线时间，作为时间线佐证。

## 4. 分段与数据库映射

| Markdown | `sections.section_type` | 说明 |
|---|---|---|
| `##` / `###` 标题 | `heading` | `body` 可为空，`heading` 存标题 |
| 普通段落 | `text` | 一段一条 |
| `**角色**：台词` | `dialogue` | `speaker` 存角色，`body` 存台词 |
| `> 选项：` + 列表 | `option` | 每个选项一条，`parent_id` 指向所属台词 |
| `> 场景：` | `note` | `body` 存场景描述 |
| `> 注：` | `note` | 明确标记为注释 |
| 其他引用 | `quote` | 保留 |
| 表格 | `table` | 可先转 Markdown 文本 |

`ordinal` 是文档内全局顺序，从 1 开始。`parent_id` 用于表达“台词 → 选项”或“小节 → 台词”。

## 5. 剧透等级

| 等级 | 含义 | 例子 |
|---|---|---|
| 0 | 无剧情信息 | 系统说明、材料描述、版本号 |
| 1 | 早期/地区级 | 序章、角色初见、地区概览 |
| 2 | 主线关键转折 | 身份揭露、重要死亡、阵营反转 |
| 3 | 终局/世界真相 | 结局、天理/深渊/坎瑞亚核心真相 |

`spoiler.scope` 用来做更细的过滤：

```yaml
spoiler:
  level: 2
  scope:
    - archon:fontaine
    - character:furina
```

查询时：

```sql
SELECT ...
FROM sections s
JOIN documents d ON d.doc_id = s.doc_id
WHERE d.spoiler_level <= :user_level
  AND d.doc_id NOT IN (SELECT doc_id FROM user_excluded_scopes ...);
```

第一版可以只按 `level` 过滤，`scope` 先做标签展示。

## 6. 标签

标签用于主题检索，不替代实体关系。建议分四类，但统一存字符串：

| 类别 | 示例 |
|---|---|
| 地区 | `蒙德`、`璃月`、`坎瑞亚` |
| 阵营/组织 | `西风骑士团`、`愚人众`、`深渊教团` |
| 概念 | `魔神战争`、`葬火之战`、`世界树`、`禁忌知识` |
| 媒介/形态 | `书籍`、`活动`、`漫画`、`公告` |

规则：

- 一个文档 3–8 个标签；
- 不用“剧情”“原神”“设定”这种无区分度的词；
- 同一概念只用一个写法，别名放 `knowledge/glossary/`；
- 标签用中文；英文名放 `title_en` 或实体别名。

## 7. 来源、哈希与版本

### 7.1 原始快照

每次抓取保存：

```text
raw/bwiki/wikitext/<page_id>-<revid>.wikitext
raw/bwiki/html/<page_id>-<revid>.html
raw/bwiki/meta/<page_id>-<revid>.json
```

`meta.json` 至少包含：

```json
{
  "url": "...",
  "status": 200,
  "fetched_at": "2026-11-04T01:30:00+08:00",
  "content_type": "application/json",
  "page_id": 8578,
  "revision_id": 123456,
  "sha256": "...",
  "source_id": "bwiki"
}
```

### 7.2 清洗后正文

- `content_hash` = 清洗后正文（不含 front matter）的 SHA-256；
- `raw_sha256` = 原始响应的 SHA-256；
- 每次重新抓取，先比 `raw_sha256`；不同再解析；
- 解析后比 `content_hash`；不同则写入 `document_revisions`；
- 不覆盖旧 revision。

### 7.3 版本与日期

- `version`：游戏实装版本，不是抓取版本；
- `version_source`：版本来自哪里（观测枢频道筛选、BWiki 字段、相关任务推导、人工、网页）；
- `version_confidence`：`confirmed` / `likely` / `inferred` / `estimated` / `unknown`；
- `retrieved_at`：抓取时间；
- `release_date`：现实上线日期；
- `timeline_entries`：世界观时间。

优先顺序：

```text
1. 观测枢任务频道 ext 的“版本号”       -> obc-filter / confirmed
2. BWiki 的“所属版本/实装版本”          -> bwiki / confirmed
3. 散落文本的“相关任务”版本             -> derived-related-quest / inferred
4. 公告日期落在官方版本上线区间          -> official / inferred（见下）
5. 官网/公告/人工核对                   -> official/manual / likely
6. 找不到                               -> version 留空 / unknown

第 4 条：官方版本更新说明自带上线日期，用发布日期落在哪个版本区间确定版本。
来源仍是官方公告，所以用 `official`；因为是区间推导而非直接标注，置信度写 `inferred`。
脚本见 `scripts/enrich_release_versions.py`。
```

“找不到”不要猜；宁可 `unknown`，也不要把 1.2 的石碑写成 6.0。

四个时间不要混。

## 8. 清洗规则

### 8.1 Wiki 模板

| 原始 | 处理 |
|---|---|
| `{{颜色|蓝|文字}}` | `文字` |
| `{{黑幕|文字}}` | `文字`，标 `spoiler` |
| `{{注音|汉字|拼音}}` | `汉字（拼音）` |
| `{{ruby|A|B}}` | `A（B）` |
| `{{任务描述|文本|地点}}` | `> 场景：文本`，地点可另起一行 |
| `{{折叠|标题=...|内容=...}}` | 保留内容，标题转为 `####` 或注释 |
| `[[页面|显示]]` | `显示`；需要实体链接时转 `[[entity]]` |
| `[[页面]]` | `页面` |
| `<br>` | 换行 |
| `&nbsp;` | 空格 |
| `<!-- ... -->` | 删除或转 `> 注：`，视内容而定 |

### 8.2 不要做的清洗

- 不把 `「」` 改成 `""`；
- 不把 `……` 改成 `...`；
- 不统一角色称号；
- 不把 `???` 推断成某个角色；
- 不删除重复台词（可能是不同分支）；
- 不合并选项分支。

### 8.3 必须检查的残留

入库前扫描：

```text
{{ ... }}
[[ ... ]]
{| ... |}
|-
&nbsp;
<br>
<nowiki>
```

有残留就标 `status: draft`，不要标 `reviewed`。

## 9. 去重与合并

### 9.1 完全重复

`content_hash` 相同：

- 只保留一篇 `documents`；
- 其他来源写入 `document_sources`；
- 不重复建 sections。

### 9.2 近似重复

同 `type` + `title` + `region`，但内容不同：

- 先判断是不是不同版本/不同语言/不同分支；
- 不同版本：保留，`version` 区分；
- 不同语言：保留，`language` 区分，`related` 互链；
- 同一版本的不同转写：选保真度高的为主，另一个挂来源，标 `transcription`。

### 9.3 系列任务与子任务

- 系列页可以生成一篇 `00-系列总览.md`，只放任务列表、版本、地区、出场人物；
- 子任务各一篇；
- 不要把系列页的摘要当成子任务正文。

## 10. 质量门禁

一篇文档从 `draft` 升到 `reviewed`，至少满足：

- [ ] front matter 通过 JSON Schema 校验；
- [ ] `source` 至少一条，URL 可访问，Wiki 有 `revision_id`；
- [ ] `sections` 非空，`ordinal` 连续；
- [ ] 没有未处理的模板/链接残留；
- [ ] 对话行要么解析成 `speaker + body`，要么明确标为普通文本；
- [ ] `content_hash` 不与已有文档重复；
- [ ] 人工抽查 10 行，与来源一致；
- [ ] 剧透等级合理；
- [ ] 标题/文件名符合规范。

`stable` 额外要求：

- [ ] 关键段落已与官方/数据包交叉校验；
- [ ] 至少一次重新抓取，确认无变化或已记录变更；
- [ ] 相关实体/文档链接已建立。
