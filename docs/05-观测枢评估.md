# 05 · 米游社·观测枢评估

> 评估时间：2026-11-04。结论：**值得作为中文结构化主源，但不能当成“官方逐字原文”。**
>
> 入口：[米游社·观测枢](https://baike.mihoyo.com/ys/obc/)

---

## 1. 它是什么

观测枢是米哈游官方平台上的原神 Wiki/资料库，页面由社区编辑维护。它比普通 Wiki 更“官方”的地方在于：

- 域名在 `baike.mihoyo.com` 下；
- 与米游社账号、官方素材、游戏数据有较深整合；
- 页面结构统一，提供搜索、频道树、结构化词条；
- 任务页里能拿到完整的对话树和选项。

但它**不是官方设定集**：

- 条目由社区编辑，可能改写、省略、滞后；
- 模块里混有攻略、配装、数值、地图说明；
- 页面有 `page_version`（编辑版本），但没有逐条官方修订记录；
- 文本的权威性仍低于游戏内原文/官方公告。

因此在本库中建议标注：

```yaml
canon_status: community        # 内容是社区维护的
transcription: near-verbatim   # 但通常是较忠实的转写
source_id: obc                 # 来源类型 official-community
version_source: obc-filter     # 版本来自哪里
version_confidence: confirmed  # 版本置信度
```

## 2. 可用的公开接口

观测枢的 Web 页面是 Nuxt SPA。页面本身不直接渲染内容，但前端会调用公开 JSON 接口。实际测试可用的接口：

### 2.1 条目页

```http
GET https://act-api-takumi-static.mihoyo.com/hoyowiki/genshin/wapi/entry_page
    ?entry_page_id=399
    &app_sn=ys_obc
    &lang=zh-cn
```

返回：

```text
data.page
├─ id / name / desc / menu_id / menu_name
├─ version                  # 页面编辑版本，不是游戏版本
├─ menus[]                  # 所属频道
└─ modules[]                # 内容模块
   ├─ name
   └─ components[]
      ├─ component_id       # role_base_info / collapse_panel / interactive_dialogue ...
      └─ data               # 通常是 JSON 字符串，需要二次 json.loads
```

需要普通浏览器 UA 和 `Referer: https://baike.mihoyo.com/ys/obc/`。

### 2.2 搜索

```http
GET https://act-api-takumi-static.mihoyo.com/hoyowiki/genshin/wapi/search
    ?keyword=钟离
    &menu_id=25
    &page_num=1
    &page_size=20
    &app_sn=ys_obc
    &lang=zh-cn
```

返回 `data.list[]`，每项有：

- `entry_page_id`；
- `name`（可能含 `<em>` 高亮）；
- `menus[]`（频道名，如“角色”“书籍”“任务”）；
- `icon_url`。

### 2.3 频道树

```http
GET https://act-api-takumi-static.mihoyo.com/common/blackboard/ys_obc/v1/getChannelTree
    ?app_sn=ys_obc
    &lang=zh-cn
```

返回完整的频道树。2026-11-04 抓到的顶层分类包括：

```text
图鉴
├─ 角色（25）
├─ 武器（5）
├─ 圣遗物（218）
├─ 书籍（68）
├─ 任务（43）
├─ 地图文本（251）
├─ 组织（255）
├─ 活动（105）
├─ 材料（13/201）
├─ 食物（21）
├─ 敌人（6）
├─ NPC&商店（20）
├─ 区域（7）
├─ 观景点（253）
└─ 考据（209）
```

这对建立“覆盖矩阵”非常有用：可以按频道统计目标数，而不是靠人工猜。

### 2.4 文章内容

较早的 Wiki 文章还有：

```http
GET https://act-api-takumi-static.mihoyo.com/common/blackboard/ys_obc/v1/content/info
    ?content_id=1053
    &app_sn=ys_obc
    &lang=zh-cn
```

返回 `data.content`，含 HTML 正文、作者、编辑者、`ctime/mtime`。适合指南/公告类文章，不如 `entry_page` 结构化。

## 3. 页面结构实测

### 3.1 任务：entry 399「序章 第一幕·捕风的异乡人」

- 88 个 module；
- 其中 **11 个 `interactive_dialogue` 剧情模块**；
- 共 65 个唯一对话节点（按 graph 去重后）；
- 约 6,454 字对话/场景文本；
- 37 个选项；
- 覆盖整幕 11 个子任务，而不是单个子任务页。

`interactive_dialogue` 的结构：

```json
{
  "root_id": "...",
  "child_ids": { "node": ["child1", "child2"] },
  "contents": {
    "node": {
      "dialogue": "<p>派蒙：...</p>",
      "option": "<p>旅行者：...</p>",
      "icon": ""
    }
  }
}
```

这说明它保存的是**对话图**，不是线性文本：

- `dialogue` 可能是一段多行台词/场景说明；
- `option` 是玩家选项；
- `child_ids` 是后续节点，多个子节点表示分支；
- 需要 DFS/BFS 展开，并处理分支汇合。

实测输出：见 `corpus/quests/archon/序章 第一幕「捕风的异乡人」.md`；任务索引见 [`corpus/quests/index.csv`](../corpus/quests/index.csv)。

### 3.2 书籍：entry 501「林间风」

- 4 个 module；
- 卷一 1,133 字，卷二 621 字；
- 与 BWiki 的《林间风》卷一对齐：

```text
BWiki 卷一：1,160 字
观测枢 卷一：1,133 字
```

差异主要是空格/分段/注释格式，正文内容基本一致。说明观测枢的书籍文本**可以用于主源**，但关键段落仍应与 BWiki/游戏内对照。

实测输出：见 [`corpus/books/蒙德/林间风.md`](../corpus/books/蒙德/林间风.md)。

### 3.3 角色：entry 1290「钟离」

- 28 个 module；
- 混有：基础信息、突破材料、推荐装备、攻略、天赋、命之座、名片、角色故事、神之心、关联语音、宣发时间轴等；
- 角色故事/描述模块（`collapse_panel`）可以直接提取；
- 属性/配装/攻略模块应过滤掉。

可保留的模块名：

```text
更多描述
角色详细
角色故事1–5
神之眼 / 神之心
角色关联语音
```

实测输出：见 `corpus/characters/璃月/钟离.md`；角色索引见 [`corpus/characters/index.csv`](../corpus/characters/index.csv)。

## 4. 与 BWiki 的分工建议

| 需求 | 首选 | 原因 |
|---|---|---|
| 任务对话/选项 | **观测枢** | 结构化对话图，整幕聚合，JSON 好解析 |
| 书籍正文 | **观测枢** | 模板字段 + 长文本，实测与 BWiki 基本一致 |
| 角色故事/语音 | **观测枢** | 模块化，能按故事/语音拆分 |
| 武器/圣遗物故事 | **观测枢** | 结构化词条，字段稳定 |
| 中文 Wiki 兜底 | **BWiki** | 页面覆盖广，任务子页线性文本便于对照 |
| 官方公告/版本信息 | **米游社** | 官方帖子，带时间和版本 |
| 结构化名称/描述 | **genshin-db** | 多语言、字段齐全，适合交叉校验 |
| 关键段落权威校验 | 游戏内/官网/数据包 | 最高优先级 |

推荐流水线：

```text
观测枢 entry_page（主源，结构化）
        │
        ├─ 任务：interactive_dialogue → 对话图 → Markdown/JSONL
        ├─ 书籍：collapse_panel → 分卷 Markdown
        ├─ 角色：故事模块 → 角色 Markdown
        └─ 物品：material_base_info + story 模块
        │
        ▼
BWiki（对照/兜底）──► 抽样比对，记录差异
        │
        ▼
SQLite + FTS
```

## 5. 优点

- **结构化**：模块/组件/字段清晰，比 wikitext 模板容易解析；
- **聚合**：一个任务入口覆盖整幕，不用逐个子任务页拼接；
- **可搜索**：自带搜索接口，能按 `menu_id` 限定频道；
- **覆盖广**：角色、武器、圣遗物、书籍、任务、地图文本、组织、考据都有频道；
- **官方平台**：素材、命名、版本信息相对规范；
- **有页面版本**：`page.version` 可用于判断是否更新。

## 6. 风险与坑

1. **社区编辑，不是官方原文**  
   关键设定必须与游戏内/官方公告/数据包交叉校验。

2. **模块顺序不是阅读顺序**  
   任务页的 module 顺序看起来是编辑顺序，不完全按剧情顺序；部分剧情模块没有场景字幕，无法自动判断属于哪个子任务。  
   当前试点用“场景字幕提取标题”，失败时用“剧情对话 N”编号，不伪造标题。

3. **对话图有分支汇合**  
   直接 DFS 会重复共同节点；需要 `seen` 去重或保留 graph 结构。当前试点做了去重，但会牺牲部分“分支上下文”。

4. **模块混杂**  
   角色页有配装/攻略/数值；任务页有奖励/地图/攻略。必须按 `component_id` 和模块名过滤。

5. **接口是前端内部接口**  
   没有公开文档，可能变更；必须限速、缓存、保留原始快照，并准备回退到 BWiki。

6. **页面版本不是游戏版本**  
   `page.version` 是编辑时间戳/版本，不是 1.0/6.0 这类游戏版本。游戏版本需要从模块字段或外部清单补。

7. **图片与富文本**  
   部分模块含图片、折叠、颜色、内链；当前只提取文本，图片标 `needs_ocr`，不假装已解析。

8. **书籍可能只有简介**  
   个别书籍 entry 只给第一卷全文，其余卷是简介（例如《白之公主与六侏儒》）。这类必须标 `notes` 并用 BWiki 补全，不能当成完整书。

## 7. 对项目的影响

### 需要改的地方

- 数据源清单增加 `obc`，类型 `official-community`；
- 默认主源从 BWiki 改为 **观测枢 + BWiki 校验**；
- 新增 `fetch_obc.py`、`render_obc.py`；
- `sections` 需要能表达对话图（至少保留 `speaker/body`，后续可加 `node_id`/`parent_node`）；
- 任务文档的 `doc_id` 可以按“观测枢 entry_page”生成，也可以拆成子任务；建议先一篇一幕，避免过早拆分；
- 角色文档只保留故事/语音模块，过滤攻略；
- 覆盖矩阵改为按频道树 + 搜索接口统计。

### 建议的验收

- 任选 3 个任务、3 本书、3 个角色，观测枢 vs BWiki 抽样对照；
- 对话节点缺失率 < 5%（以观测枢为基准，BWiki 为对照）；
- 选项不丢；
- 每条正文可回到 `entry_page_id + page_version + module index`；
- 关键设定句与官方/数据包对照至少 10 条。

## 9. 版本标记与散落文本（2026-11-04 补充）

### 9.1 频道列表接口

除了搜索，观测枢还有一个更适合做覆盖统计的接口：

```http
GET https://act-api-takumi-static.mihoyo.com/common/blackboard/ys_obc/v1/home/content/list
    ?channel_id=68
    &page_num=1
    &page_size=1000
    &app_sn=ys_obc
    &lang=zh-cn
```

返回 `data.list[0].list[]`，每个条目包含：

- `content_id`：通常就是 `entry_page_id`；
- `title`；
- `ext`：JSON 字符串，里面有筛选器，例如：

```json
{"c_43":{"filter":{"text":"[\"任务类型/魔神任务\",\"任务地区/蒙德\",\"版本号/1.0\"]"}}}
```

实测数量（2026-11-04）：

| 频道 | 条目数 | 版本筛选 |
|---|---:|---|
| 任务（43） | 1,101 | 有“版本号” |
| 书籍（68） | 93 | 无 |
| 地图文本（251） | 706 | 无 |
| 角色（25） | 138 | 无 |
| 武器（5） | 252 | 无 |
| 圣遗物（218） | 63 | 无 |

### 9.2 版本从哪里来

优先顺序：

```text
1. 任务：观测枢任务频道 ext 的“版本号”          -> obc-filter / confirmed
2. 书籍、角色、武器、圣遗物：BWiki 的“实装版本” -> bwiki / confirmed
3. 散落文本：从“相关任务”推导                    -> derived-related-quest / inferred
4. 官网/公告/人工核对                            -> official/manual / likely
5. 找不到                                        -> unknown / unknown
```

散落文本的例子：

- `残破的笔记【废弃避难所】` → 相关任务 `月之东，日之西·物归原主` → `版本号/月之一` → `6.0`（inferred）；
- `散落的书页【揭示之书】` → 相关任务 `秘诲揭示之书` → `版本号/4.0` → `4.0`（inferred）；
- `石碑【龙脊雪山】` → 没有相关任务字段 → 版本留空，标 `unknown`，不猜。

版本映射表在 [`../manifests/versions.csv`](../manifests/versions.csv)，标签映射在 [`../manifests/version-labels.csv`](../manifests/version-labels.csv)。

书籍版本覆盖：BWiki SMW 一次返回 105 条书籍，OBC 的 93 本里匹配到 92 本；只剩 `残破的笔记`（book 1158）没有可靠版本，标 `unknown`。多卷本可能跨版本，例如《白夜国馆藏》标 `2.3–2.4`。

已入库书籍：92/93。`503 林间风·故事拔萃节选` 是 `501 林间风` 的重复卷，标 `skipped-duplicate`，不重复入库。

### 9.3 散落文本的结构

地图文本 entry 通常只有 3 个 module：

```text
0. <标题>        map_desc            # 地图截图/坐标，跳过
1. 交互文本      interactive_dialogue # 正文，保留
2. 相关任务      collapse_panel      # context，放 notes 或元数据
```

所以散落文本用：

```yaml
type: lore
subtype: scattered
```

正文只保留“交互文本”，**不提取地图截图和坐标**；相关任务只作为版本推导/上下文。

### 9.4 本轮的格式决定

- 任务：**一篇一幕**；子任务用 `##` 分节。
- 对话：**分支去重**，共同节点只渲染一次；完整图仍保留在 raw JSON。
- 草稿：**留在 `exports/`**，确认后再进 `corpus/`。
- 角色：**只保留故事/描述/语音**，去掉属性、命之座、配队、攻略。
- 图片：**尽量不提取**；需要时标 `needs_ocr`，不假装已解析。

实测输出：

```text
exports/obc-evaluation/lore-507704.md   残破的笔记（6.0 inferred）
exports/obc-evaluation/lore-503070.md   散落的书页（4.0 inferred）
exports/obc-evaluation/lore-501754.md   石碑（unknown）
```

### 9.5 一个注意事项

频道列表里的 `content_id` 通常等于 `entry_page_id`，但不总是：

- `林间风` 的系列页是 `501`；
- 频道列表里列的是卷一 `503`；
- 两者都能抓，但不要把系列页和单卷页当成同一篇文档。

抓取时先按 `entry_page_id` 存 raw，再在文档层合并/关联。

## 10. 抽样对照（2026-11-04）

完整报告：[`../exports/obc-evaluation/crosscheck.md`](../exports/obc-evaluation/crosscheck.md)。

样本：5 本书、5 个任务、5 条散落文本。

### 书籍

| 书 | OBC 字符 | BWiki 字符 | 比例 |
|---|---:|---:|---:|
| 林间风 | 2,044 | 2,445 | 0.84 |
| 石书辑录 | 558 | 453 | 1.23 |
| 绝云记闻 | 5,128 | 4,268 | 1.20 |
| 白之公主与六侏儒 | 793 | 344 | 2.31（OBC 仅第一卷全文） |
| 白夜国馆藏 | 6,873 | 6,032 | 1.14 |

除部分文本外，OBC 与 BWiki 量级基本一致；差异来自分段、注释和 BWiki 字段截取。

### 任务结构

修复 `interactive_dialogue` 的两种格式后：

```text
任务 entry：1,101
有对话段：1,051
无对话段：68
```

之前的 576 条“无对话”里，有 381 条是 OBC 的 graph-only 格式（`contents + root_id` 单独成组，没有 `list` 包装），旧渲染器只读 `list`，所以漏掉了。修复后已恢复，例如 `quest.obc.7609「大梦的醒转」` 从 60 字符恢复到 58 个对话段。

剩余 50 条是 OBC 本身没有可渲染对话的系列/总览页，如 `第二章 第二幕「无念无想，泡影断灭」`、`第二章 第四幕「回响渊底的安魂曲」`。这些页的子任务名只是 `base_info` 模块，不是独立 entry，无法靠合并子页解决，需要 BWiki/游戏数据补正文。

本轮已用 BWiki 子任务页补全 181 条；剩余 50 条在 BWiki 也没有可解析的 `==任务剧情==`，多为邀约/活动/地区系列页。

所以：

- 版本全量补齐（1,101/1,101）；
- 1,051 条有对话，50 条是缺正文的系列页，已标记待补，不能当完整任务。

### 散落文本

- BWiki 没有对应地图文本页面，无法独立逐字对照；
- OBC 正文与 raw JSON 一致；
- 版本只能从相关任务/成就/活动推导：226/706 有版本，480 条保持 `unknown`。
