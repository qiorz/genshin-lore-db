# 01 · 数据源与合规

> 实测时间：2026-11-04（Asia/Shanghai）。站点状态会变，下面的“实测”只代表当时、当前网络环境。
>
> **2026-11-04 更新**：新增“米游社·观测枢”作为中文结构化主源。它的 entry_page 接口能直接给出任务对话图、书籍分卷、角色故事模块；详见 [`05-观测枢评估.md`](05-观测枢评估.md)。

---

## 1. 结论先行

建议的组合：

```text
中文结构化/剧情主源：观测枢（官方平台，社区编辑；entry_page JSON）
中文 Wiki 校验/兜底：BWiki（MediaWiki API + wikitext）
官方公告/版本信息：米游社（帖子 API）
结构化名称/描述：genshin-db（npm 数据包）
权威抽查：原神官网、游戏内文本、数据包
英文/日文对照：Fandom、wikiwiki.jp（可选）
```

不建议：

- 把米游社当成“全文剧情库”——大量内容在图片里，且帖子质量参差；
- 把观测枢当成“官方逐字原文”——它是官方平台、社区编辑，必须标 `community` / `near-verbatim`；
- 直接整站爬 BWiki 而不做页面类型区分——模板和子页面会把解析器拖垮；
- 把 Wiki 的转写当成逐字官方文本——必须标注 `transcription`；
- 把社区数据包当成“无版权数据”——代码许可不等于数据授权。

## 3. 各来源的用法与坑

### 3.1 米游社·观测枢：结构化主源

**定位**：米哈游官方平台上的原神 Wiki，条目由社区编辑维护。它比普通 Wiki 更结构化，但不能当成官方逐字原文。

**可用接口**：

```text
GET /hoyowiki/genshin/wapi/entry_page?entry_page_id=399&app_sn=ys_obc&lang=zh-cn
GET /hoyowiki/genshin/wapi/search?keyword=钟离&menu_id=25&page_num=1&page_size=20&app_sn=ys_obc&lang=zh-cn
GET /common/blackboard/ys_obc/v1/getChannelTree?app_sn=ys_obc&lang=zh-cn
GET /common/blackboard/ys_obc/v1/home/content/list?channel_id=68&page_num=1&page_size=1000&app_sn=ys_obc&lang=zh-cn
```

**频道列表**：一次返回该频道的全部条目（书籍 93、地图文本 706、任务 1,101），`ext` 里带筛选器；任务的 `ext` 有“版本号”，可直接标 1.0/4.0 等。书籍/散落文本没有版本字段，需要 BWiki 或“相关任务”推导。

**最适合**：

- 任务：`interactive_dialogue` 模块，含对话树、选项、场景说明；
- 书籍：`collapse_panel` 里的 `rich_text`，按卷拆分；
- 散落文本：地图文本频道的 `交互文本`，跳过 `map_desc` 图片；
- 角色：`collapse_panel` 里的角色故事/描述/语音；
- 武器/圣遗物/材料：结构化词条；
- 频道列表：建立覆盖矩阵和版本索引。

**坑**：

- 页面模块顺序不等于阅读顺序；
- 模块混有攻略/配装/数值，需要过滤；角色只保留故事/描述/语音；
- 图片（地图截图、图标）不默认提取；
- `page.version` 是页面编辑版本，不是游戏版本；
- 版本字段不是每个频道都有：任务有“版本号”，书籍/散落文本没有；
- 接口没有公开文档，可能变更，必须限速/缓存/保留快照。

实测数据、接口结构和与 BWiki 的对照见 [`05-观测枢评估.md`](05-观测枢评估.md)。

### 3.2 BWiki：中文 Wiki 校验/兜底

> 角色调整：观测枢为主源；BWiki 用于覆盖补缺、线性对照和异常页面兜底，不再作为唯一主源。

**为什么仍然保留它**

- 中文，页面结构和原神文本类型对得上；
- 任务页分为“系列任务页”和“单任务子页”，子页有 `==任务剧情==`，按步骤分节；
- 书籍页把每一卷的内容放在 `卷N内容` 字段；
- 角色页有资料、故事、语音等区块；
- 有 `实装版本`、`任务地区`、`任务类型` 等结构化字段，适合做覆盖统计；
- MediaWiki API 可以拿 `wikitext`、渲染 HTML、`revid`，便于做来源追踪。

**页面结构示例（任务子页）**

```text
{{任务
|任务名称=...
|任务地区=蒙德
|任务类型=魔神任务
|系列任务=序章,捕风的异乡人
|任务编号=01
...
}}
==任务剧情==
===继续前进===
{{任务描述|...|蒙德 坠星山谷}}
===到派蒙附近===
*派蒙：...
```

**典型模板/语法**

- `{{任务描述|...|地点}}`：场景描述；
- `*角色：台词`：对话行；
- `{{颜色|蓝|文字}}`：颜色标记，清洗时保留文字；
- `{{折叠|...}}`：折叠内容，仍要保留；
- `{{黑幕|...}}`：剧透/隐藏文本，保留但标 `spoiler`；
- `[[链接|显示名]]`：内部链接，转换成 `[[实体]]` 或纯文本；
- `<br>`：换行；
- `{{#ask:...}}`：SMW 查询，渲染 HTML 时才有结果。

**坑**

- 系列任务页本身可能只有模板和子任务列表，正文在子页；
- 同一任务可能有“活动任务”同名页，需要按 `任务类型` 区分；
- 页面可能被编辑、重命名、合并；
- 部分 API 请求会返回 567/403，需要限速和重试；
- 许可未在 API 中明示，按“个人研究使用”处理。

**建议抓取流程**

1. 用 `list=search` 或 `list=allpages` 建立页面清单；
2. 用 `action=parse&prop=wikitext|revid` 保存原始 wikitext；
3. 另存 `action=parse&prop=text` 的渲染 HTML，用于对照模板展开结果；
4. 解析 `{{任务}}`/`{{书籍}}`/`{{角色}}` 字段；
5. 按 `任务剧情`、`卷N内容`、角色故事等区块切分；
6. 写入 `raw/` + `corpus/`，并记录 `revid`。

### 3.3 米游社：官方公告与版本信息

**适合**

- 版本更新说明、活动公告；
- 官方角色/剧情宣传；
- 开发者访谈、设计说明；
- 官方发布的短篇设定、漫画/视频配套文字。

**不适合**

- 作为完整剧情文本库：很多帖子是截图、拼图、二创；
- 作为唯一来源：帖子可能被编辑、删除、折叠。

**API 实测**

```text
GET https://bbs-api.miyoushe.com/post/wapi/getPostFull?post_id=<id>
GET https://bbs-api.miyoushe.com/post/wapi/getForumPostList?forum_id=26&gids=2&num=20
```

需要：

```text
User-Agent: <普通浏览器 UA>
Referer: https://www.miyoushe.com/ys/
```

实测：

- `getPostFull` 返回 200，JSON 中含 `post.post.content`（HTML）；
- `getForumPostList` 返回 200，可列出论坛帖子；
- `getPostList`、`searchPost` 返回 404（路径可能已变，别依赖）；
- 直接 `web_fetch` 不带 headers 会 403。

**策略**

- 维护一个**人工策展的 post_id 清单**（版本公告、官方设定文），不要盲扫 ID；
- 用论坛列表发现官方账号/置顶帖；
- 正文 HTML 清洗成 Markdown；
- 图片单独下载或标记 `needs_ocr`，不要把图片当已入库文本；
- 控制频率，默认 1 请求/秒。

### 3.4 原神官网

- 首页是 Nuxt/JS 应用，直接抓 HTML 只能拿到壳；
- 角色、地区、漫画等页面可能需要找内部 JSON 接口，或用浏览器渲染后保存；
- 权威性高，但覆盖面不如 Wiki；
- 适合做**关键段落的权威抽查**，不适合作为批量主源。

### 3.5 genshin-db

- npm 包，提供 JSON 数据；unpkg 可直接浏览；
- 测试时包版本 5.2.12，README 标注 v6.7 数据；
- 适合：名称、描述、故事、语音、材料等结构化字段；
- 不适合：完整任务对话（它不是任务文本库）；
- 数据来源标注为 Fandom + GenshinData，属于二手/数据包，不是官方 API；
- 代码许可与数据权利分开看。

**用法建议**

- 只取需要的字段，不整包复制；
- 记录包版本和字段路径；
- 与 BWiki/游戏内文本交叉校验；
- 不要把它当成“官方原文”的唯一证据。

### 3.6 Fandom

- 英文 Wiki，任务、角色、书籍页面齐全；
- 通常按 CC BY-SA 许可，公开复用时需要署名/相同方式共享；
- 本次网络访问失败，可能是网络/地区/反爬；
- 如果可用，适合做英文对照和结构参考，不建议作为中文主源。

### 3.7 HoYoWiki

- 官方 Wiki，多语言，权威性高；
- 本次返回 403（地区限制）；
- 如果换网络可用，适合做官方词条校验；
- 不作为第一版依赖。

### 3.8 数据包（AnimeGameData / GenshinData）

- 能拿到游戏内精确字符串，适合校验 Wiki 转写；
- GitHub 访问、许可证、版本稳定性都需要先确认；
- 不要绕过客户端访问控制；
- 只保留本项目需要的文本字段，不整体再分发。

### 3.9 其他 Wiki / 数据站

- wikiwiki.jp：日文全文质量较高，适合对照；
- Honey/Yatta/Paimon.moe：物品/怪物/成就数据，不是叙事主源；
- 任何站点都先看 `robots.txt` 和条款，再决定是否自动抓取。

## 4. 来源质量阶梯

同一段文本如果有多个来源，按以下顺序取“更接近原文”的版本：

```text
1. 游戏内文本 / 官方客户端数据
2. 官方站点原文
3. 官方社交账号/米游社官方帖
4. 官方平台/社区编辑（观测枢 entry_page）
5. 社区数据包（genshin-db / AnimeGameData）
6. Wiki 逐字转写（BWiki 等）
7. Wiki 编辑/摘要
8. 玩家考据/二手总结
```

但“更权威”不等于“更好用”：

- 游戏内文本最准，但提取成本高；
- 观测枢结构化最好，但仍是社区编辑，必须标 `community`；
- BWiki 覆盖广、线性文本好读，适合对照/兜底；
- 三者应**并存**：观测枢做结构与覆盖，BWiki 做交叉核对，官方/数据包做关键段落校验。

在 front matter 中用两个字段区分：

- `canon_status`：这段内容在世界观意义上的权威性；
- `transcription`：这份文本相对原文的保真度。

例如：

```yaml
canon_status: community          # 内容是官方平台上的社区编辑
transcription: near-verbatim     # 但文本通常是较忠实的转写
```

## 5. 抓取与合规规则

### 必须做

- 设置真实、可识别的 User-Agent；
- 默认 1 请求/秒，遇到 429/567 退避；
- 缓存响应，避免重复请求；
- 保存 URL、时间、状态码、`revid`、哈希；
- 遵守 `robots.txt` 和站点条款；
- 只抓公开页面；
- 对图片文本单独标记，不假装已解析。

### 不能做

- 绕过登录、付费、验证码、访问控制；
- 伪造 Cookie / 盗用他人账号；
- 对站点进行高压并发抓取；
- 把全文公开转载或做成镜像站；
- 把“抓取成功”当成“可以任意使用”。

### 建议的请求配置

```toml
[http]
request_interval_seconds = 1.0
timeout_seconds = 30
max_retries = 3
backoff_seconds = 2
```

## 6. 本项目的来源策略

### 第一阶段（试点）

- 观测枢：1 个魔神任务系列 + 1 本书 + 1 个角色；已验证 399 / 501 / 1290；
- BWiki：对同一任务/书籍做抽样对照；
- 米游社：1 篇版本公告/官方设定文；
- genshin-db：只取对应名称/描述做交叉校验；
- 官网：只做 1 次关键段落抽查。

### 第二阶段（叙事全量）

- 观测枢为主，按频道树（任务/书籍/角色/武器/圣遗物/地图文本）分批；
- BWiki 作为兜底/校验，尤其是观测枢缺页、模块异常、文本明显不完整时；
- 米游社补官方公告和活动说明；
- genshin-db 补结构化字段；
- 对 P0 文本做抽样对照（官方/数据包）。

### 第三阶段（知识层）

- 以 `corpus/` 和 `db/` 为证据，人工建立实体、关系、时间线；
- 每条 claim 必须能落到 `section_id`；
- 无法落地的说法，标 `unsourced`，不进入“已确认”层。
