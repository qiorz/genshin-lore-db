# 迁移与交接

> 2026-11-12 · 给接手的人

## 1. 这是什么

一个**本地可跑的原神世界观数据库**：把官方公告、任务、书籍、角色页、武器圣遗物描述等
7,734 篇文本切成 453,939 段存进 SQLite，再在其上叠一层人工整理的知识图谱
（400 个实体、215 条关系、364 条说法），并提供一个不依赖联网的检索界面。

三件事同时成立：

1. **原文层**可以被全文检索（FTS5），每段都能定位到「哪篇文档的第几段」；
2. **知识层**的每一条断言都能点回原文那一句，没有出处的结论不收；
3. **原始检索界面零改动**——第二轮开发加的知识层是并列的一层，没有覆盖原来的搜索结果页。

## 4. 数据怎么流动

这是理解项目最重要的一节。四层单向流动，**不要反向手改下层**：

```text
raw/*.json  ──解析──▶  corpus/*.md  ──导入──▶  SQLite(原文层)
                                              │
knowledge/seed*.yaml ──灌库──▶ SQLite(知识层) ┘
        │                            │
        └──导出──▶ knowledge/entities/*.md ──▶ Web UI 读库渲染
```

### 改知识层的正确顺序

```bash
# 1. 改种子（或改生成脚本的候选表，重新生成种子）
# 2. 干跑校验：只报告，不写库
tools/python/python.exe scripts/load_knowledge.py
# 3. 落库（--prune 会删掉「种子里已经没有了」的实体/关系/别名/机器说法）
tools/python/python.exe scripts/load_knowledge.py --apply --prune
# 4. 重导卡片
tools/python/python.exe scripts/export_entity_cards.py --apply
# 5. 清过期卡（实体换类型后旧目录会留副本）
tools/python/python.exe scripts/prune_cards.py --apply
# 6. 看覆盖率变化
tools/python/python.exe scripts/audit_entities.py --write
```

`load_knowledge.py` 是幂等的：固定主键 + upsert，重复跑行数不变。

## 5. 关键设计决定（以及为什么）

| 决定 | 原因 |
|---|---|
| 知识层与原文层分表，`entities` 不侵入 `documents` | 原搜索界面一行代码不改，回滚成本为零 |
| 每条关系/说法都必须有 `doc_id + quote`，灌库时现场解析 `section_id` | 抗重导：语料重切后段落 id 会变，靠原话重新定位 |
| 实体出处单列 `entity_evidence`，与 `claims` 分开 | `claims` 是「带立场的断言」，`evidence` 只回答「原文提到过它」 |
| 别名独立成批（`seed-stage9.yaml`） | 写在实体批次里会被生成脚本重写，丢过 19 条 |
| 卡片、报告全部是生成物 | 手改会在下次生成时消失，且无法追溯 |
| 复核结论单独存 `review-state.yaml` | 同上：不改生成物，只覆盖状态 |
| 一条关系没原话就不建 | 「迪卢克与凯亚是义兄弟」人人知道，但库里 23 段共现没有一句这么写，所以不收 |

## 6. 踩过的坑（别重复踩）

1. **批处理必须 GBK + CRLF**。UTF-8 保存的 `.cmd` 会让 `cmd.exe` 把中文行截断，
   实测 `start` 那行被吃掉，表现为「脚本跑了但服务没起来」。
2. **生成脚本必须对自己产物幂等**。`build_stage4.py` 曾用「库里已有同名实体」判重，
   重跑时全部跳过，连分类写错都改不了；一次空跑还把种子覆盖成 0 条。
   现在统一读「上一次的种子拿 id 白名单」或「库里 id − 其他批次 id」。
3. **多锚点实体不能直接 LEFT JOIN**。一个实体有 3 条出处时，JOIN 会让它在列表里出现 3 次。
   复核队列改成「先取主锚点一张表，再按 id 对回」。
4. **子串不是共现**。`璃月港` 含 `璃月`、`蒙德城` 含 `蒙德`，按字面算永远「共现」。
   匹配前先判断两名是否互为子串，是就返回 0 分。
5. **版式行不是证据**。`璃月 天衡山`、`【璃月总务司公告】`、`蒙德观光指南·风起地`
   都是索引行。有 `usable()` 闸门过滤。
6. **同一对实体只留一条归属边**。曾同时存在 `located_in 蒙德` 与 `based_in 蒙德`，
   页面显示两行。现在按 `(subject, object)` 去重。
7. **批量替换前确认字符串唯一**。`t.replace(old, new, 1)` 替换
   `相关时间线 {len(tl_rows)} 条`，而它在列表页和详情页各有一份，结果命中了列表页，
   引用了一个只存在于详情页的变量，`/entities` 直接 500。
   → 改成先 `assert text.count(old) == 1`。
8. **手拼 YAML 会被特殊字符写坏**。`statement: *斜体*` 是合法的别名语法，
   生成时要么加引号要么用 `yaml.safe_dump`。
9. **`python -c` 里的正则会被 shell 吃反斜杠**。`\s`、`\S` 会变形，
   导致「重复卡片 0 张」的假阴性。这类检查一律写成脚本文件。

### 如果新设备没有便携 Python

装 Python 3.11+ 后 `pip install -r requirements.txt`，脚本里把
`tools/python/python.exe` 换成 `python` 即可。所有脚本都用
`Path(__file__).resolve().parent.parent` 定位项目根目录，**没有硬编码盘符**
（已检查，仅两处历史脚本曾硬编码，已修）。

### 路径注意

- 项目可以放在任意盘符、任意目录，但**不要放在含中文或空格的路径**下
  （`start.cmd` 里 `%~dp0` 能处理空格，但个别抓取脚本的 URL 拼接会出问题）。
- 数据库是单文件 SQLite，**不要用网盘同步目录**（WAL 模式在多端并发下会损坏）。
- 数据库已于 2026-11-12 做过 `VACUUM`（384 → 356 MB），打包用的是压缩后的库。
- 库的 `journal_mode` 是 `delete`（`VACUUM INTO` 生成的新库默认如此）。
  **这是故意保留的**：单文件自包含，不会出现 `-wal` 丢了导致数据不一致。
  要改回 WAL，执行 `PRAGMA journal_mode=WAL;` 即可，但那样打包时要把
  `-wal`/`-shm` 一起带走，反而多一层出错的可能。
