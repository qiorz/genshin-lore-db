## 阶段 1 · 试点竖切（建议 1–2 天）

目标：用 15–20 篇不同形态的文本，把“抓取 → 原始快照 → 清洗 → Markdown → 入库 → 检索 → 人工核对”全部跑通。

### 1.1 任务

1. **抓取器**
   - `fetch_obc.py`：抓观测枢 entry_page / search / channel_tree（已实现）；
   - `fetch_bwiki.py`：按页面名/页面 ID 抓 `wikitext`、`revid`、渲染 HTML（校验用）；
   - `fetch_miyoushe.py`：按 `post_id` 抓公告正文；
   - 统一限速、重试、缓存、`meta.json`。

2. **解析器**
   - `render_obc.py`：任务 `interactive_dialogue`、书籍 `collapse_panel`、角色故事模块、散落文本 `交互文本`（试点版已实现）；
   - `render_obc.py` 读取 `manifests/versions.csv` 补 `version/source/confidence`；
   - `parse_bwiki_quest.py`：系列任务 → 子任务 → `==任务剧情==`，作为对照/兜底；
   - `parse_bwiki_item.py`：武器/圣遗物模板 + 故事字段。

3. **规范化**
   - `validate_frontmatter.py`：front matter schema 校验（已实现）；
   - `load_markdown.py`：front matter + 段落/台词/选项 → SQLite（已实现）；
   - `search.py`：FTS5 trigram 中文检索（已实现，2 字词 LIKE 兜底）；
   - `segment_zh.py`：分词逻辑已并入 `load_markdown.py`，后续可抽出。

4. **入库**
   - `init_db.py`：执行 `schema/schema.sql` + `schema/fts.sql`；
   - `load_corpus.py`：解析 Markdown → `documents` / `sections` / `document_sources`；
   - `search.py`：命令行检索，支持 `--type`、`--region`、`--spoiler`。

5. **质检**
   - `validate.py`：front matter schema、模板残留、重复哈希、空章节；
   - `coverage.py`：按类型/地区/版本统计；
   - 人工抽查 10 段。

### 1.2 交付物

```text
corpus/...                     15–20 篇 Markdown
raw/...                        对应原始快照 + meta.json
db/genshin_lore.sqlite3        可检索数据库
exports/pilot-report.md        试点报告（成功/失败/待修）
scripts/*.py                   可重跑的脚本
```

- [ ] `check_env.ps1` 全部通过；
- [ ] 15–20 篇覆盖至少 5 种类型；
- [ ] 每篇有来源、版本或 `unknown` 标记、抓取时间、哈希；
- [ ] 任务文本能解析到“说话者 + 台词”，选项不丢；
- [ ] 书籍多卷不丢卷；
- [ ] 角色页只保留叙事内容，不混入配队/数值；
- [ ] SQLite 能按关键词 + 类型 + 地区 + 剧透等级检索；
- [ ] 搜“钟离”“坎瑞亚”“派蒙”至少各返回一条正确段落；
- [ ] 重复运行不会产生重复文档；
- [ ] 人工抽查 10 段与来源一致。

## 阶段 2 · 叙事文本扩量（建议 1–2 周，按可用时间推进）

目标：把“读世界观必须看”的文本先收全，不追求全游戏所有字符串。

### 2.1 优先级

| 批次 | 内容 | 说明 |
|---|---|---|
| P0-1 | 书籍 | 历史/神话/寓言，信息密度最高 |
| P0-2 | 散落文本（地图文本） | 石碑、笔记、留言、书页；只收交互文本 |
| P0-3 | 魔神任务（序章 → 当前） | 世界观主干；一篇一幕 |
| P1-1 | 角色故事 + 描述 + 语音 | 只收游戏内文本，去攻略/配队/数值 |
| P1-2 | 传说任务 | 角色背景、地区史 |
| P1-3 | 世界任务 | 地区细节、支线设定 |
| P1-4 | 活动剧情 | 限时内容，优先补 |
| P1-5 | 武器/圣遗物故事 | 碎片化远古设定 |
| P2-1 | 材料/食物/道具描述 | 批量生成，逐条校对 |
| P2-2 | 地理志/地区文本 | 与地图、任务交叉 |
| P2-3 | 官方公告/版本页 | 时间线佐证 → **已完成**：53 篇版本更新说明 + 2 篇活动公告 |
| P3 | NPC 全部对话、漫画、PV | 噪声/跨媒介，最后做 → **NPC 对话已完成** 2,401 篇；漫画/PV 仍未做 |

### 2.2 每批的流程

```text
建页面清单
  → 抓取（断点续跑）
  → 解析（失败单独列出）
  → 规范化
  → 入库
  → 覆盖统计
  → 抽样核对
  → 修解析器
  → 下一批
```

### 2.3 交付物

- 覆盖矩阵：每类“已入库/待补/解析失败/不适用”；
- 失败清单：页面名、URL、失败原因；
- 版本变更清单：哪些页面 `revid` 变了；
- 抽样核对记录：至少每类 10 段。

### 2.4 验收标准

- [ ] P0 覆盖率达到团队/个人设定的目标（建议先 90% 以上）；
- [ ] 解析失败页面有明确原因，不静默丢失；
- [ ] 同一文档不会因重复抓取产生多份；
- [ ] 每篇 `status` 至少为 `draft`，核心文本为 `reviewed`；
- [ ] 可按地区/版本/类型输出统计。

## 阶段 3 · 知识层（贯穿始终，P0 文本完成后加速）

目标：从“能搜到原文”升级到“能比较说法、理清关系”。

### 3.1 先做 50 个核心实体

建议范围：

- 七神与魔神：钟离、温迪、影、纳西妲、芙宁娜、玛薇卡、冰之女皇等；
- 国家/地区：蒙德、璃月、稻妻、须弥、枫丹、纳塔、至冬、坎瑞亚；
- 组织：西风骑士团、愚人众、深渊教团、往生堂、教令院等；
- 核心概念：天理、世界树、地脉、神之眼、邪眼、禁忌知识、葬火之战、魔神战争、坎瑞亚灾变；
- 关键非人存在：派蒙、旅行者、反主、三月女神、龙族等。

每个实体：

```yaml
id: entity.zhongli
type: character
canonical_name: 钟离
aliases: [摩拉克斯, 岩王帝君, 契约之神, ...]
spoiler_level: 2
tags: [璃月, 七神, 往生堂]
```

### 3.2 再做关系

先做高价值关系：

- `is` / `alias_of`：身份；
- `member_of`：组织；
- `rules` / `governs`：统治；
- `located_in`：地理；
- `participated_in`：事件；
- `created` / `destroyed` / `sealed`：行为；
- `knows` / `suspects`：认知；
- `opposes` / `allies_with`：阵营。

每条关系必须能指向至少一个 `section_id` 或明确标 `unsourced`。

### 3.3 再做时间线

- 先做“相对顺序”，不急着绝对年份；
- 用 `timeline_entries.sort_key` 排序；
- 每条标 `certainty`；
- 争议处并列，不强行合并；
- 现实版本时间线单独一张表/视图，不混入提瓦特纪年。

### 3.4 最后做 claims

优先处理：

- 同一事件的不同说法；
- 角色身份/动机的争议；
- 书籍/传说与主线冲突处；
- 玩家社区长期争论的设定。

每条 claim：

```text
主体 + 谓语 + 客体
+ 原始陈述/摘要
+ 视角（谁说的）
+ 来源 section
+ confidence / status
```

### 3.5 验收标准

- [ ] 50 个核心实体有别名和简介；
- [ ] 每个实体至少 3 条有来源的关系；
- [ ] 一条可追溯的主时间线（相对顺序 + 关键绝对年代）；
- [ ] 至少 20 条争议 claim，能并列展示不同说法；
- [ ] 任一结论可点击回到原文段落。

## 阶段 4 · 检索与阅读体验

### 4.1 先做 CLI / SQL

- `search.py "关键词"`；
- `--type quest --region 璃月 --spoiler 1`；
- `--context 2` 显示上下文；
- 输出 `doc_id`、标题、段落、来源 URL。

### 4.2 再做 Obsidian

- 根目录直接作为 vault；
- front matter 变属性；
- `[[entity.zhongli]]` 双链；
- 用 Dataview（可选）做“某地区的任务”“某角色的故事”列表；
- 用 Canvas 做关系图/时间线（可选）。

### 4.3 可选：本地 Web UI

只在 CLI/Obsidian 不够时做：

- 简单搜索页 + 筛选；
- 段落阅读 + 来源侧栏；
- 剧透过滤；
- 不做用户系统、不做公网部署。

### 4.4 验收标准

- [ ] 搜索延迟 < 1 秒（本地库）；
- [ ] 结果能定位到段落和来源；
- [ ] 剧透过滤有效；
- [ ] 可按实体反查出现段落；
- [ ] 不需要联网即可阅读。

## 阶段 5 · 维护

每个版本更新后：

1. 拉取关注页面的新 `revid`；
2. 对比 `raw_sha256`；
3. 变化的页面重新解析；
4. 写入 `document_revisions`；
5. 生成变更清单；
6. 人工确认关键设定变化；
7. 更新知识层中受影响的实体/时间线/claims。

### 验收标准

- [ ] 能列出“本版本哪些文本变了”；
- [ ] 旧版本仍可查；
- [ ] 知识层变更有记录，不悄悄改结论。
