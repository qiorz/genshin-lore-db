典型：`蒙德城`、`海灯节`、`深渊` 三张卡除了 3 条出处，其余全空；
`西风骑士团` 有 11 条边，但说法 0、时间线 0。

### 结论：不是数据不够，是**每层只铺了一条窄通道**

| 层 | 现在怎么来的 | 覆盖到谁 | 为什么别处是空的 |
|---|---|---|---|
| 关系 | `mine_relations.py` 只挖 3 组类型对：人物→组织、地点→国家、组织→国家 | 110 个实体 | 事件、生物、概念、人物↔人物 完全没有通道 |
| 说法 | 只读角色页的「角色关联语音」 | 65 个角色/神明 | 地点、组织、生物、事件、国家 没有来源 |
| 时间线 | 只能通过 `involved_in` 反查 `timeline_entries` | 12 个实体 | 8 个纪年事件只连了 17 个实体；18 个节庆/事件实体不在 `events` 表里，天然没时间线 |
| 别名 | 人工词表 25 条 + 严格挖 11 条 | 48 个实体 | 只覆盖了部分角色称号；国家、组织、地点一个没做 |

## 2. 补救方案

### A. 关系：106 → 约 265 条

| 子项 | 做法 | 可补 | 风险 |
|---|---|---:|---|
| A1 地点→国家 | 62 个地点人工归属（58/62 语料有同段共现作证据），其余留空 | +55 | 低：国家归属是硬事实 |
| A2 组织→国家 | 35/35 有同段共现，人工确认后写 `based_in` | +33 | 低 |
| A3 事件→国家 | 18 个节庆/事件确认举办国，新增 `held_in` | +13 | 低 |
| A4 生物→分布 | 只收「出没于/栖息于」明确句式 | +10 | 中：多数生物是泛分布，不硬塞 |
| A5 人物↔人物 | 亲属 11 对 + 同僚/师徒/敌对句式 | +20 | 中：需要句式约束 |
| A6 事件参与 | 8 个纪年事件补 `involved_in`（谁参与） | +40 | 中：需从事件文档里确认参与者 |

A1–A3 是「人工给结论、脚本找出处」，和之前的 25 条别名同一套路，可信度最高。

### B. 说法：233 → 约 600 条，覆盖 65 → 200+

| 子项 | 做法 | 可补 | 风险 |
|---|---|---:|---|
| B1 任务对话 | `sections.speaker` 明确 + 句中只出现一个实体 + 评价词 + 长度 15–80 | +400~600 | **高**：容易把"顺带提到"当成"评价"，必须抽检 20% |
| B2 争议说法 | 书籍/任务里的「据说/有人认为/传说」句式 | +30 | 中 |

B1 是唯一能大幅提升说法覆盖的来源（6109 段候选），但也是噪声最高的一条，
建议先出 200 条候选 → 人工筛 → 再批量。

### C. 时间线：12 → 80+，另有 191 个角色

| 子项 | 做法 | 可补 |
|---|---|---:|
| C1 事件参与 | 同 A6，参与实体自然带上时间线 | 80 个实体 |
| C2 角色实装版本 | 角色页 `version` + 53 条 release 时间线 → 「X.Y 版本上线」 | 191 个角色 |
| C3 事件实体 | 节庆给「首次实装版本」，不给虚构年份 | 18 个事件 |

C2 要说清是**游戏版本**，不是提瓦特纪年——两条线在 UI 上已分开，不能混。

### D. 别名：59 → 约 120 条

| 子项 | 例子 | 可补 |
|---|---|---:|
| D1 国家别称 | 蒙德=风之国、璃月=岩之国、枫丹=水之国…（语料 3–26 段） | +8 |
| D2 组织简称 | 西风骑士团→骑士团、璃月七星→七星 | +15 |
| D3 角色称号补漏 | 放宽「XX」+名 的挖掘后人工确认 | +40 |
| D4 地点别名 | 只收确实的（如 稻妻城=稻妻首府） | +5 |

## 3. 建议顺序

1. **D 别名**（半天，零风险）——立刻改善「别名少」
2. **A1/A2/A3 关系**（一天，低风险）——同时带动时间线 C1
3. **C2 角色版本**（半天）——191 个角色都有时间线
4. **B1 说法**（一到两天，高风险）——必须抽检，放最后

验收标准：每张卡至少 1 条边 + 1 条说法 + 1 个别名；仍为空的要有明确理由
（例如「史莱姆」这种泛分布生物可以没有归属边）。

## 4. 复跑方式

```bash
python scripts/audit_entities.py --write    # 重新生成 exports/review/entity-coverage.md
```

体检只看四个数字，不看总量——总量足够但覆盖率为 27% 时，卡片体验仍然是空的。

### 怎么做出来的

`knowledge/curated-facts.yaml` 写结论（每条 107 条归属 + 45 条别名），
`scripts/apply_curated.py` 去语料里找出处，够硬才写。结论怎么定的：
先跑 `scripts/probe_geography.py` 让语料投票（哪个国家同段最多、有没有
「X位于Y」这类句式），人再确认。

这一步不是形式主义。`希汐岛` 的初判是「纳塔」，语料显示它在挪德卡莱附近
（「两片古月遗骸落到了挪德卡莱，一片落到了希汐岛」）；`赤王陵` 按同段
统计会落到「至冬」（因为那句在说「没有至冬纹样，他才敢说是赤王陵挖来的」）。
凭记忆填，这两条都会错。

### 没做的与做不到的

| 项 | 为什么 |
|---|---|
| 天云峠 / 三界路飨祭 / 清籁逐雷记 | 语料里各只有 2 篇提及，找不到可用出处，宁可空着 |
| 无相交响诗 / 葬火之战 / 魔女的茶会 | 跨国或地点不明，无国家归属 |
| 冒险家协会 / 深渊教团 / 盗宝团 | 跨国组织，`based_in` 单国会误导 |
| 地点别名 | 全是正名子串（层岩巨渊→巨渊、稻妻城→稻妻），检索上没有增量 |
| 组织别名 | 同上（千岩军→千岩、西风骑士团→西风、教令院→教令） |

**「别名越多越好」是错的**。中文组织简称几乎都是原名的子串，收进来只是
让检索结果里多一条重复命中。这一轮真正收到的是国家别称（风之国/岩之国…）
和能唯一指认的角色称号（侦察骑士/决斗代理人/马力卜）。

顺带清掉一个错别名：`教令院 ← 贤者`——「贤者」是教令院的职位，不是它的别名。
